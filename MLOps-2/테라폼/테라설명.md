좋아. 이제 이 구조를 “진짜 실무 CI/CD + 멀티 레지스트리 + 멀티 환경”까지 확장해서 **현업 수준으로 굴러가는 형태**로 정리해줄게.

핵심은 딱 3개야:

> 1. GHCR/ECR 둘 다 지원
> 2. Terraform은 배포만 책임 (image build 제외)
> 3. 환경(dev/stg/prod)은 완전히 분리 + state 분리

# 1️⃣ 전체 흐름 (실무 표준 파이프라인)

```text id="p9k2wq"
GitHub Actions
   ↓
Docker Build
   ↓
Push (GHCR or ECR)
   ↓
Terraform Apply (env별)
   ↓
EC2 or ECS Runtime Deploy
```

# 3️⃣ registry_router (핵심 설계)

👉 “ECR vs GHCR 자동 선택 레이어”

### 🔹 modules/registry/registry_router/main.tf

```hcl id="r4k9z1"
module "ecr" {
  source = "../ecr"
  count  = var.type == "ecr" ? 1 : 0
  name   = var.name
}

module "ghcr" {
  source = "../ghcr"
  count  = var.type == "ghcr" ? 1 : 0
  name   = var.name
}
```

---

### 🔹 outputs.tf (중요)

```hcl id="k2x9pp"
output "image_uri" {
  value = var.type == "ecr"
    ? module.ecr[0].repository_url
    : module.ghcr[0].image_url
}
```

---

💡 핵심:

* runtime은 registry 타입 몰라도 됨
* 항상 `image_uri`만 받음

# 4️⃣ GHCR module (실무형)

# 5️⃣ app deploy (핵심 orchestration layer)

```hcl id="v8kq2a"
module "registry" {
  source = "../../modules/registry/registry_router"

  type = var.registry_type
  name = var.app_name
}

module "runtime" {
  source = "../../modules/runtime/${var.runtime_type}"

  app_name = var.app_name
  image    = module.registry.image_uri
}
```

# 6️⃣ EC2 runtime (실전형 systemd docker 방식)

```hcl id="c9q2lz"
resource "aws_instance" "app" {
  ami           = var.ami_id
  instance_type = var.instance_type

  user_data = <<-EOF
    #!/bin/bash
    docker pull ${var.image}

    cat <<EOT > /etc/systemd/system/app.service
    [Unit]
    Description=App

    [Service]
    ExecStart=/usr/bin/docker run --rm -p ${var.port}:8080 ${var.image}
    Restart=always

    [Install]
    WantedBy=multi-user.target
    EOT

    systemctl daemon-reload
    systemctl enable app
    systemctl start app
  EOF
}
```

# 9️⃣ GitHub Actions (실전 CI/CD)

```yaml id="g7k9qq"
name: deploy

on:
  push:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: Build Docker
        run: docker build -t myapp .

      - name: Login GHCR
        run: echo $TOKEN | docker login ghcr.io -u USER --password-stdin

      - name: Push image
        run: |
          docker tag myapp ghcr.io/myorg/myapp:latest
          docker push ghcr.io/myorg/myapp:latest

  deploy:
    needs: build
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: Terraform apply
        run: |
          cd terraform/envs/dev
          terraform init
          terraform apply -auto-approve
```

# 🔟 전체 구조 핵심 요약

## ✔️ registry layer

* ECR / GHCR 추상화
* image URI만 제공

## ✔️ runtime layer

* EC2 / ECS interchangeable
* 실행 방식만 다름

## ✔️ app layer

* registry + runtime 연결

## ✔️ env layer

* dev/stg/prod 완전 분리
* state 분리 필수

# 🔥 이 구조의 진짜 장점

### 1) Cloud lock-in 없음

* GHCR ↔ ECR 자유 교체

### 2) runtime swap 가능

* EC2 → ECS → Kubernetes

### 3) CI/CD 독립

* Terraform은 배포만 담당

### 4) 실무 확장성

* 팀 구조 그대로 확장 가능
