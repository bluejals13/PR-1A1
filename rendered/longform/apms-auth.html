1. 무상태(Stateless) 인증의 보안 딜레마 DOCUMENTED
Stateless JWT는 서명 검증만으로 인가가 가능하여 확장성이 높지만, '발급된 토큰의 즉시 회수 불가(Token Revocation Gap)'라는 태생적 보안 취약점이 존재합니다. 로그아웃 후에도 토큰 만료 시간까지 비인가 접근이 가능한 취약점을 방어해야 했습니다.
Core Dilemma 로그아웃 요청 후에도 탈취된 Access Token으로 정상 API 인가가 통과되는 보안 홀 발생.
2. 3중 보안 방어선 및 Lua Script RTR 의사결정 VERIFIED
순수 DB 세션 방식은 동시성 부하 시 I/O 병목을 유발하므로, 1시간 Stateless Access Token과 In-Memory Redis Blacklist, 1-RTT 원자적 Lua Script RTR을 결합한 3중 보안 계층을 채택했습니다.
Architectural Decision 1차 Access Token 고속 검증 ➔ 2차 Redis Blacklist 즉시 차단 ➔ 3차 Lua Script RTR 재사용 방어
3. 토큰 라이프사이클 및 시퀀스 아키텍처 VERIFIED
Nginx(Port 80)를 단일 진입점으로 하여 Spring Boot API 서버와 In-Memory Redis 7 간의 토큰 발급/검증/폐기 흐름을 격리 구성했습니다.
// Authentication Sequence: Login ➔ Normal API Call ➔ Immediate Logout Invalidation
[Step 1] Client ➔ Nginx:80 ➔ POST /api/auth/login ➔ Redis SET refresh:user (TTL 7d) ➔ Access (Bearer) + Refresh (HttpOnly Cookie)
[Step 2] Client ➔ Nginx:80 ➔ GET /api/users/me ➔ 1) JWT 서명 검증 ➔ 2) Redis Blacklist 확인 ➔ 200 OK
[Step 3] Client ➔ Nginx:80 ➔ POST /api/auth/logout ➔ Redis SET blacklist:{jti} (TTL 잔여시간) ➔ 즉시 무효화
