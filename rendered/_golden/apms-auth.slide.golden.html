무상태(Stateless) JWT의 보안 딜레마: 즉시 세션 무효화의 한계

Takeaway: 확장성을 유지하면서 즉시 로그아웃과 토큰 탈취를 방어할 3중 계층 설계 필요
Core Dilemma 무상태 JWT는 DB 부하를 줄이지만, 발급된 토큰을 중간에 폐기할 수 없는 Token Revocation Gap이 존재합니다.

• RDBMS 세션: 즉시 제어 가능하나 I/O 병목 발생
• 순수 JWT: 확장성 높으나 즉시 로그아웃 불가
• 목표: 확장성과 실시간 세션 통제력의 동시 확보

[ Problem Boundary Matrix ]
❌ Stateful Session: DB Connection Pool Exhaustion
⚠️ Pure JWT: Cannot Revoke Stolen Tokens
✓ APMS Hybrid: Stateless + In-Memory Blacklist
