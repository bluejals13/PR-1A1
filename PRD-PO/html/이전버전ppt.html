SLIDE 04 // SECURITY DESIGN BEFORE & AFTER

보안 아키텍처: 단순 JWT vs 3중 방어 체계

무상태 토큰에 실시간 무효화 및 재사용 탐지 능력 부여
VERIFIED
BEFORE: Simple JWT Only VULNERABLE

순수 무상태 설계로 인해 서버 측 통제 수단 부재

  • 로그아웃 무력화: 로그아웃 후에도 Access Token(1시간)이 유효하여 API 호출 허용됨.
  • Replay Attack 위험: 탈취된 Refresh Token으로 누구나 지속적으로 토큰 재발급 가능.
  • 권한 통제 한계: 단순 Role 문자열 기반으로 세부 권한 분기 불가.
AFTER: 3-Layer Defense (JWT + RTR + Redis) VERIFIED

무상태 확장성과 실시간 보안 통제력의 결합

  • Layer 1 [Access Token (1h)]: Header Bearer 전송, JJWT 서명 검증으로 고속 무상태 인가.
  • Layer 2 [RTR (7d)]: HttpOnly Secure Cookie 전달, 재발급 시 기존 JTI 즉시 파기 및 1회용 소진. 탈취 토큰 재요청 시 즉시 401 차단.
  • Layer 3 [Redis Blacklist]: 로그아웃 시 Access Token 잔여 수명만큼만 `bl:` 적재. 필터에서 즉시 차단.
  • Layer 4 [M:N RBAC]: User ↔ Role ↔ Permission 다대다 정규화 인가 필터링.
