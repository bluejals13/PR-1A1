SLIDE 02

무상태(Stateless) 인증의 3대 보안 딜레마 & 해결 아키텍처

ARCHITECTURAL DECISION
1. Token Revocation Gap 무효화 불가
로그아웃 후에도 토큰 유효

순수 Stateless JWT는 사용자가 로그아웃해도 만료 시각(1시간)까지 서명이 유효하여 토큰 탈취 시 API 호출을 즉시 차단할 방법이 없음.

2. Replay Attack Risk 탈취 토큰 재사용
장기 Refresh Token 공격 노출

7일간 유효한 Refresh Token이 고정되어 있으면 탈취 시 공격자가 무한히 새 Access Token을 발급받아 지속적인 비인가 접근 가능.

3. Container Isolation 도커 루프백 실패
`localhost` 바인딩 거부

Docker 격리 환경에서 컨테이너 간 통신 시 `localhost`는 자기 자신을 가리켜 Redis/DB 커넥션 거부(Connection Refused) 발생.

SLIDE 07

실제 장애 3건의 계층별 엔지니어링 대응 (Incident Map)

TS 6-STEP STANDARD
APP DATA LAYER TS-01-REDIS
Redis 커맨드 타임아웃 블로킹
SYMPTOM

Redis 장애 시 백엔드 스레드가 최대 60초간 블로킹되어 프론트엔드 흰 화면(Blank Screen) 발생

ROOT CAUSE

Lettuce 클라이언트 기본 커맨드 타임아웃(60s) 미설정 및 스레드 고갈

RESOLUTION

타임아웃 2초(`2000ms`) 단축 및 503 `REDIS_UNAVAILABLE` 즉시 반환

CLIENT / NETWORK LAYER TS-001
JWT Refresh 401 무한 루프
SYMPTOM

토큰 만료 시 클라이언트 인터셉터와 서버 간 초당 수십 회 401 재시도 루프로 CPU 급증

ROOT CAUSE

갱신 요청 실패(401)에 대한 클라이언트 탈출 조건(Exit Condition) 부재

RESOLUTION

갱신 401 수신 시 세션 즉시 초기화 및 로그인 리다이렉트 탈출 로직 구현

INFRA CONTAINER LAYER TS-003
Docker Redis 바인딩 거부
SYMPTOM

`docker compose up` 실행 시 Spring Boot가 Redis 연결에 실패하며 기동 중단

ROOT CAUSE

컨테이너 격리 환경에서 `localhost`는 컨테이너 자신(Loopback)을 가리키는 문제

RESOLUTION

`${SPRING_REDIS_HOST:localhost}` 환경변수화 및 서비스명(`redis`) 주입
