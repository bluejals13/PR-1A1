02. Security & Authorization

Stateless JWT + RTR + Redis Blacklist

무상태 인증의 확장성을 유지하면서도 토큰 탈취와 즉시 로그아웃을 완벽하게 제어합니다.

Token Lifecycles
VERIFIED
  • Access Token: 1시간 (3,600,000ms), Authorization Header (Bearer) 전달
  • Refresh Token: 7일 (604,800,000ms), HttpOnly Secure Cookie 전달
  • JJWT 기반 Payload에 userId, roles, permissions 포함
Refresh Token Rotation (RTR)
VERIFIED
  • 재발급 요청 시 Redis(`rt:`) 내 UUID JTI 검증
  • 검증 즉시 기존 JTI 삭제 및 신규 세트 동시 발급
  • 이미 소진된 구버전 JTI 재요청 시 즉시 401 차단 (Replay Attack 방어)
Redis Token Blacklist
VERIFIED
  • 로그아웃 시 Access Token을 `bl:` 키로 Redis 등재
  • Access Token의 잔여 만료시간만큼만 TTL 부여
  • 무상태 토큰임에도 로그아웃 즉시 인가 필터에서 차단
M:N RBAC Authorization Model
VERIFIED

User ↔ Role ↔ Permission 정규화 매핑 구조. 세부 엔드포인트 권한 인가 필터링을 통해 권한 없는 사용자의 관리자 리소스 접근 시 403 Forbidden 반환 검증 완료.

Flyway Schema Migrations
IMPLEMENTED

`V1__init_schema.sql`부터 `V5__insert_test_users.sql`까지 5단계 버전 스크립트를 통해 DDL 형상을 100% 코드로 통제하고 불일치 방지.

04. Incident Troubleshooting

TS 표준 6단계 장애 해결 사례

Symptom ➔ Impact ➔ Diagnosis ➔ Root Cause ➔ Resolution ➔ Prevention

[TS-01] Redis 타임아웃 지연
VERIFIED
  • 현상: Redis 장애 시 백엔드가 최대 1분간 블로킹되며 프론트엔드 빈 화면 발생
  • 원인: Lettuce 클라이언트 기본 타임아웃(60초) 미설정
  • 해결: 타임아웃을 2초(`2000ms`)로 단축하고 `RedisUnavailableException` 503 반환
[TS-001] JWT 무한 루프
VERIFIED
  • 현상: Refresh Token 만료 시 클라이언트 인터셉터와 서버 간 401 무한 재시도 루프
  • 원인: 갱신 실패 응답에 대한 클라이언트 탈출 조건(Exit Condition) 결여
  • 해결: Single Flight 토큰 재발급 패턴 적용 및 401 시 즉시 세션 초기화/리다이렉트
[TS-003] Docker Redis 바인딩
VERIFIED
  • 현상: `docker compose up` 실행 시 Redis Connection Refused 발생
  • 원인: 컨테이너 환경에서 `localhost`는 컨테이너 자신을 가리키는 고립 문제
  • 해결: `docker-compose.yml`에 `SPRING_REDIS_HOST: redis` 주입 및 환경변수화
