SLIDE 06

RTR(Refresh Token Rotation) 및 Redis Blacklist 토큰 상태 제어

VERIFIED DOCUMENTED

1. Refresh Token Rotation (RTR)

1회용 JTI 검증

토큰 갱신 시마다 JTI를 교체하여 재사용 공격(Replay Attack) 방어

Step 1
토큰 갱신 요청: Cookie의 Refresh Token(`JTI_A`) 전달
Step 2
원자적 교체: Redis `rt:`의 `JTI_A` 삭제 및 신규 `JTI_B` 발급
Defend
탈취 토큰 재사용 거부: 이미 소진된 `JTI_A`로 재요청 시 즉시 401 Unauthorized 차단

2. Redis Token Blacklist

잔여 TTL 관리

로그아웃 시 Access Token의 잔여 수명 동안만 메모리에 적재하여 즉시 무효화

Step 1
로그아웃 요청: `/api/auth/logout` 호출 시 Access Token 파싱
Step 2
TTL 계산 & 적재: 남은 만료 시간(예: 35분)만큼 Redis bl:<token> 등록
Result
즉시 필터 차단: `JwtAuthenticationFilter`에서 O(1) 인메모리 확인 후 401 Unauthorized 거부
Architectural Advantage 매 API 요청마다 DB 세션을 조회하지 않아 Stateless의 고성능을 유지하면서, 토큰 탈취 대응 및 즉각적인 실시간 세션 통제권을 동시에 확보.
