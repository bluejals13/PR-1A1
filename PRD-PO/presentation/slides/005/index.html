SLIDE 05

JWT 이원화 수명주기 및 전송 채널 물리 격리

IMPLEMENTED VERIFIED
Short-Lived Token 1 HOUR TTL

Access Token

전송 채널: Authorization: Bearer <token> (Header)
  • 목적: 모든 인가 API 요청 시 즉각적인 무상태 서명 검증
  • 페이로드: `userId`, `roles`, `permissions`를 포함하여 DB 조회 최소화
  • 특징: 1시간 짧은 만료 주기로 탈취 시 피해 노출 시간 제한
  • 저장소: 클라이언트 메모리(State) 관리
Long-Lived Token 7 DAYS TTL

Refresh Token

전송 채널: HttpOnly; Secure; SameSite=Strict (Cookie)
  • 목적: Access Token 만료 시 재발급 엔드포인트(`/api/auth/refresh`) 전용
  • 식별자: 난수 UUID 기반 `jti` 식별자로 Redis(`rt:<userId>`) 매핑
  • 보안 격리: HttpOnly 플래그로 브라우저 JavaScript(XSS) 접근 원천 차단
  • 전송 제어: `SameSite=Strict` 설정을 통해 CSRF 요청 차단
