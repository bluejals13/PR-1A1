Decision 01 Stateless Access Token vs Stateful Session
Pure Stateless JWT

✔ 서버 메모리/DB 부하 제로
✖ 발급된 토큰 즉시 무효화 불가

VS
Stateful Session

✔ 즉각적인 세션 무효화 가능
✖ 매 요청 DB/세션 스토리지 부하

선택: 하이브리드 아키텍처

Access Token은 무상태(1h)로 서명 검증하여 성능을 극대화하고, 로그아웃 및 토큰 재발급 시에만 Redis Blacklist/RTR을 조회하여 타협점 도출.

Decision 02 Redis 의존성 결합 vs 시스템 복원력
기본 설정 (Lettuce 60s)

✔ 일시적 네트워크 지연 복구 대기
✖ Redis 다운 시 60초 블로킹 전파

VS
Fast-Fail 격리 설계

✔ 2초 타임아웃으로 스레드 보호
✖ Redis 다운 시 토큰 갱신 503 중단

선택: 2초 타임아웃 & 503 격리

Redis 장애가 전체 백엔드 톰캣 스레드 풀 고갈로 전파되는 최악의 상황을 방지하기 위해 타임아웃 2초 단축 및 503 에러 핸들링으로 장애 격리.
